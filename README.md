# 定禅寺通りイベントカレンダー

公開ページ：https://everydaylogic.github.io/jozenji-calendar/

定禅寺通りまわりのイベント（Rensa・東京エレクトロンホール宮城・仙台三越 催物場・勾当台公園）と
一番町健診クリニックの健診日を、**GitHub Actions ＋ ローカルLLM（Ollama）** で週1回自動で集めて表示します。
Claude のサブスクリプションが無くても動き続けます。

Claude が更新している [jozenji-display](https://github.com/everydaylogic/jozenji-display)（本番）も並行して動いており、
毎回その結果と見比べています（このリポジトリは、もとは本番の控え `jozenji-display-test` として作ったもの）。
画面（`docs/`）と公開用データの作り方（`tools/build_events_json.py`）は本番と同じです。

## 動かし方

1. 「Actions」タブ →「イベントデータの更新」→「Run workflow」
2. 終わったら、その実行のページの一番下に結果（サイトごとの件数・時間・本番との違い）が出ます
3. 変更があれば `docs/events.json` が更新され、Pages に反映されます

最初は `only` に `mitsukoshi,morisanho` を入れると、LLMを使わない部分だけを数分で確認できます。

## 何をどう取っているか

| サイト | 取り方 | LLM |
|---|---|---|
| Rensa | 月別スケジュール3か月分のHTMLを、ページの作り（日付・出演者・タイトルの欄）から読む | 使わない |
| 東京エレクトロンホール宮城 | 催事予定表PDFの表＋主催公演一覧のHTMLを、欄ごとに読む | 使わない |
| 仙台三越 催物場 | イベントJSON＋催物ご案内PDF（帯の表を線と文字の位置から読む） | 使わない |
| 勾当台公園 | 市の公園イベント案内の表（使わない）／光のページェント公式・まとめサイト（使う） | 一部使う |
| 一番町健診クリニック | 年間スケジュールPDFの色分けを読む（新しいPDFのときだけ） | 使わない |

最初の試験（全部LLMで読む方式）は1時間48分かかり、Rensa とホールで日付の取り違えが多かったため、
作りの決まっているページはLLMを使わずに読む方式に切り替えた。
LLMへの問い合わせは結果を `data/llm_cache.json` に残し、ページが変わっていなければ使い回す。

LLMの出力は、タイトルがページの本文に実在するかを照合し、無いもの（作り話）は捨てています。
取れなかったサイトは前回のデータを残します。

## 天気（今日の予定の画面）

今日と明日の天気・降水確率（午前・午後・夜）・最高/最低気温を、気象庁の宮城県の予報から出しています。
天気と降水確率は「宮城県東部」、気温は「仙台」。ページを開いたときと30分おきに、ページが気象庁から直接読み込むので、
GitHub Actions の更新とは関係なく、気象庁の発表（5時・11時・17時）がそのまま反映されます。
今日の最低気温は気象庁の予報に無い（5時の発表にも無い）ため、仙台の観測（アメダス）の「0時から今までの最低」を出します。
17時の発表からは今日の最高気温も予報から消えるので、そのあとは観測の「今日の最高」を出します（予報より観測が高くなったときも観測）。

## ファイル

```
updater/run.py            更新の本体（サイトごとに実行 → events.json 作成 → 結果の報告）
updater/sites.py          サイトごとの取り方
updater/llm.py            本文の整形・Ollama 呼び出し・作り話の除去
updater/mitsukoshi_pdf.py 三越の催物ご案内PDFの読み取り
updater/clinic_pdf.py     クリニックの年間スケジュールPDFの読み取り
updater/dates.py          和暦などの日付の統一
data/sources/*.json       サイトごとのデータ（前回分。毎回書き換え）
data/clinic_calendar.json 健診の年間スケジュール
data/last_run.md          直近の更新結果
docs/                     公開ページ（本番と同じ）
tools/                    公開用 events.json の作成（本番と同じ）
```

## 問題があったときの連絡

毎回の更新の最後に、次のどれかに当てはまれば Issue を立てて持ち主に知らせる（開いている Issue があれば追記）。

- どれかのサイトが取れなかった（前回のデータをそのまま表示している）
- 今月・来月の件数が、比べる相手の半分未満に減った（サイトの作りが変わった可能性）
- 処理そのものが途中で止まった
- 本番（Claude）の更新が止まっている（`COMPARE_WITH_PROD` が "on" のときだけ。本番のデータが、直近の日曜朝の定期更新より前に作られたままなら知らせる。Claude の使用量の上限に達したときなど）

比べる相手は `.github/workflows/update.yml` の `COMPARE_WITH_PROD` で決まる。

- `"on"`（今）… 本番（Claude が更新している jozenji-display）の events.json と比べる
- `"off"` … 先週の自分の events.json と比べる。**本番（Claude）の更新をやめたら、ここを "off" にする**
